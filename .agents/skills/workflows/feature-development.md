# workflow-feature-development

## Purpose
High-level orchestration skill for end-to-end feature development.

## When to Use
When starting any new feature across the stack.

## When NOT to Use
For small bug fixes or documentation typos.

## Required Context
- User requirements

## Inputs
- Feature specifications

## Expected Outputs
- Fully implemented, tested, and documented feature.

## Rules & Constraints
1. Conform strictly to the canonical architecture.
2. Complete all steps sequentially.

## Step-by-Step Workflow
1. repository-exploration
2. architecture-discovery
3. impact-analysis
4. domain modeling
5. database design + Flyway migration
6. backend service + repository + entity
7. REST controller + DTOs
8. RabbitMQ events if needed
9. Redis caching if needed
10. unit + integration tests
11. API docs update
12. client implementation
13. security review
14. documentation sync
15. git commit

## Validation Checklist
- [ ] Definition of Done met.
- [ ] No architecture violations.

## Common Mistakes
- Skipping architecture discovery.
- Forgetting Flyway migrations.
- Writing features without tests.

## Example Usage
Follow this file as a checklist for large features.
