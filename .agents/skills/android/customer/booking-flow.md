# customer-booking-flow

## Purpose
Skill for Customer Android booking flow. Cover: service selection, address selection, slot picker (from /api/v1/scheduling/availability), pricing display (server-calculated), payment initiation, booking confirmation screen.

## When to Use
When developing the step-by-step booking process in the Customer App.

## When NOT to Use
For Admin booking creation (which uses different APIs).

## Required Context
- Endpoints for availability and pricing

## Inputs
- Selected service

## Expected Outputs
- Complete booking workflow

## Rules & Constraints
1. Pricing MUST be calculated by the server.
2. Slots MUST be fetched live from the backend.
3. Use Room and WorkManager sparingly here; bookings require online access.

## Step-by-Step Workflow
1. Fetch available slots from `/api/v1/scheduling/availability`.
2. Present UI for slot and address selection.
3. Fetch calculated price from server.
4. Initiate payment flow.
5. Confirm booking on success.

## Validation Checklist
- [ ] Pricing is strictly server-driven.
- [ ] Slots reflect true availability.
- [ ] Booking confirmation handles edge cases gracefully.

## Common Mistakes
- Calculating prices on the client side.
- Assuming a slot is confirmed before backend returns success.

## Example Usage
Use Retrofit to call endpoints and update ViewModels.
