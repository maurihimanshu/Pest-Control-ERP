# customer-auth-flow

## Purpose
Skill for Customer Android Firebase Auth flow. Cover: phone OTP with Firebase, Google Sign-In, ID token retrieval, Retrofit Authorization header, token refresh.

## When to Use
When building the authentication flows for the native Android Customer App.

## When NOT to Use
Do not use for Admin Web or Technician offline auth logic.

## Required Context
- Firebase Android SDK setup

## Inputs
- UI designs for login

## Expected Outputs
- Firebase Auth integration
- Retrofit Interceptor

## Rules & Constraints
1. MUST use Firebase Authentication for identity.
2. Inject Firebase token into Retrofit headers as Bearer token.
3. Native Android Java 21 implementation.

## Step-by-Step Workflow
1. Setup Firebase Phone Auth & Google Sign-In.
2. Capture credentials and authenticate.
3. Retrieve Firebase ID Token.
4. Implement Retrofit Interceptor to attach token.
5. Handle 401 token refresh automatically.

## Validation Checklist
- [ ] Phone OTP works.
- [ ] Google Sign-In works.
- [ ] Tokens are attached to all API requests.
- [ ] Token refresh handles expiration smoothly.

## Common Mistakes
- Storing the token manually instead of letting Firebase SDK manage it.
- Failing to handle 401 Unauthorized responses.

## Example Usage
```java
public class AuthInterceptor implements Interceptor {
    // Add Bearer token to request
}
```
