# spring-security-config

## Purpose
Skill for configuring Spring Security 6.x. Cover: SecurityFilterChain, stateless sessions, CSRF disabled for API, FirebaseAuthenticationFilter in filter chain, permitAll vs authenticated paths.

## When to Use
When setting up or modifying API security configurations and endpoints.

## When NOT to Use
Not for client-side authentication or arbitrary legacy security frameworks.

## Required Context
- Existing REST controllers
- Endpoints that should be public vs protected

## Inputs
- Desired access rules

## Expected Outputs
- Configured SecurityFilterChain bean

## Rules & Constraints
1. MUST use stateless sessions.
2. CSRF disabled for APIs.
3. Use FirebaseAuthenticationFilter.
4. NO Firestore usage. Database is PostgreSQL.
5. All endpoints /api/v1/** must be secured by default.

## Step-by-Step Workflow
1. Define public paths (e.g., webhooks, public catalogs).
2. Configure HTTP security builder.
3. Set session creation policy to STATELESS.
4. Disable CSRF.
5. Insert Firebase filter before UsernamePasswordAuthenticationFilter.
6. Verify rules in integration tests.

## Validation Checklist
- [ ] Stateless sessions confirmed.
- [ ] CSRF is disabled.
- [ ] Filter chain includes Firebase filter.
- [ ] Public paths are explicitly permitAll.
- [ ] All other paths require authentication.

## Common Mistakes
- Enabling CSRF for stateless REST APIs.
- Forgetting to register the Firebase filter.
- Using stateful sessions in a distributed architecture.

## Example Usage
```java
@Bean
public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
    http.csrf(csrf -> csrf.disable())
        .sessionManagement(session -> session.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
        ...
}
```
