# api-security

## Purpose
Skill for API security. Cover: input validation with Bean Validation, rate limiting (Redis), HMAC verification for payment webhooks, secure file upload, idempotency keys, no sensitive data in logs.

## When to Use
When exposing any new endpoint or webhook to the internet.

## When NOT to Use
Do not use to bypass Spring Security.

## Required Context
- Redis configuration
- Validation dependencies

## Inputs
- Payload definitions

## Expected Outputs
- Secured API endpoints

## Rules & Constraints
1. MUST use Bean Validation (`@Valid`, `@NotNull`, etc.).
2. Use Redis for rate limiting.
3. Validate all webhooks with HMAC.
4. No PII in logs.

## Step-by-Step Workflow
1. Add validation annotations to DTOs.
2. Configure Redis sliding window rate limiter.
3. Implement HMAC verification filter for webhooks.
4. Mask sensitive data in logger configs.

## Validation Checklist
- [ ] DTOs are strictly validated.
- [ ] Redis rate limits are active.
- [ ] Webhooks verify HMAC signatures.
- [ ] Logs are clean of passwords and tokens.

## Common Mistakes
- Forgetting `@Valid` on controller parameters.
- Logging full request payloads including passwords.
- Not verifying webhook signatures.

## Example Usage
```java
@PostMapping("/webhook")
public ResponseEntity<Void> handleWebhook(@RequestHeader("X-Signature") String signature, @RequestBody String payload) {
    // Verify HMAC
}
```
