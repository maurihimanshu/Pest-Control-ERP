# rbac

## Purpose
Skill for RBAC. Cover 7 roles: SUPER_ADMIN, ADMIN, DISPATCHER, AGENCY_MANAGER, ACCOUNTANT, TECHNICIAN, CUSTOMER. Cover @PreAuthorize with SpEL, method-level security, resource ownership checks. NEVER client-side role checks.

## When to Use
When restricting access to specific APIs based on user roles or resource ownership.

## When NOT to Use
Never rely on client-side checks for security.

## Required Context
- User entity and assigned roles
- Resource ownership rules

## Inputs
- Endpoints
- Authorized roles

## Expected Outputs
- Method-level security annotations

## Rules & Constraints
1. MUST conform to Canonical Architecture.
2. NEVER client-side role checks.
3. Use SpEL for ownership validation.

## Step-by-Step Workflow
1. Identify required roles for an endpoint.
2. Add `@PreAuthorize("hasRole('ADMIN')")` or similar.
3. For ownership, use `@PreAuthorize("@securityService.isOwner(authentication, #id)")`.
4. Write security tests.

## Validation Checklist
- [ ] 7 standard roles are supported.
- [ ] Method security is enabled.
- [ ] Tests verify unauthorized access returns 403.
- [ ] Resource ownership is enforced.

## Common Mistakes
- Trusting the client to hide UI elements without backend enforcement.
- Using `@Secured` instead of `@PreAuthorize` (missing SpEL support).

## Example Usage
```java
@PreAuthorize("hasAnyRole('SUPER_ADMIN', 'ADMIN')")
@GetMapping
public List<User> getUsers() { ... }
```
