# security-review

## Purpose
Skill for reviewing code for security issues. Cover: authentication gaps, authorization gaps, injection risks, sensitive data exposure, insecure direct object references, missing idempotency.

## When to Use
During code reviews or dedicated security audits.

## When NOT to Use
For functional testing.

## Required Context
- Source code changes

## Inputs
- Git diffs

## Expected Outputs
- Security findings

## Rules & Constraints
1. MUST conform to Canonical Architecture.
2. Flag any hardcoded secrets immediately.
3. Ensure no IDOR vulnerabilities exist.

## Step-by-Step Workflow
1. Check authentication (are endpoints secured?).
2. Check authorization (are roles/ownership verified?).
3. Check for SQL/NoSQL injection vectors.
4. Verify sensitive data isn't logged.
5. Check for missing idempotency keys on mutations.

## Validation Checklist
- [ ] No unauthenticated sensitive endpoints.
- [ ] IDOR checked and prevented.
- [ ] Proper error handling (no stack traces in responses).

## Common Mistakes
- Approving PRs without checking `@PreAuthorize`.
- Missing idempotency checks on payment endpoints.

## Example Usage
Use this checklist against any feature branch before merging to main.
