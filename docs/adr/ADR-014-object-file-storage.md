# ADR-014: Object File Storage

**Status:** Accepted
**Date:** September 2026
**Deciders:** Principal Architect, Product Owner

## Context
Large binary files should not bloat the PostgreSQL database. Must be scalable and provider-neutral.

## Problem
How to store and serve binary files securely (inspection photos, customer signatures, invoice PDFs, etc.)?

## Decision
Binary files stored in provider-neutral Object Storage (AWS S3 / Google Cloud Storage / Cloudflare R2 compatible). Metadata (file_name, mime_type, size, storage_key, agency_id, entity_type, entity_id, access_policy, checksum_sha256) stored in PostgreSQL file_metadata table. Pre-signed URLs generated by backend — never expose raw storage credentials to clients. Access authorization checked before generating pre-signed URL.

## Alternatives Considered
| Alternative | Reason Rejected |
|:---|:---|
| Store BLOBs in PostgreSQL | poor scalability, expensive backups |
| Firebase Storage without authorization check | files exposed to anyone with URL |
| Store in CDN directly | no authorization control |

## Consequences
### Positive
- Scalable, cost-effective storage.
- Secure, authenticated access via pre-signed URLs.

### Negative / Trade-offs
- Requires maintaining dual state (DB metadata + Object Storage).
